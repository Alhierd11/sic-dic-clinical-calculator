# Security policy

Only the current development branch is maintained; no production security support or response-time guarantee is offered yet. Do not use development builds for clinical decisions.

Never submit patient data, signing keys, access tokens or exploitable details in public issues. If GitHub private vulnerability reporting is enabled, use the repository Security → Report a vulnerability flow. If unavailable, open a minimal public request for a private reporting channel without technical details or sensitive data; wait for the maintainer to establish it. No contact address is invented here.

Report version/commit, synthetic reproduction, impact and mitigations privately. Arithmetic defects that could mislead clinicians require prompt investigation, regression vectors and a documented correction; they are not merely cosmetic bugs. Releases require dependency review, static analysis and closure of critical findings.
